# `.clubs/club.yaml` reference

Generated by `club init`, validated by every other command via `validator.validate_club`.
All fields below are Pydantic models in `src/clubs/models.py` — additive changes to
this schema always ship with safe defaults, so an older `club.yaml` keeps working
after an upgrade (e.g. `provider: dummy` if you never set it).

```yaml
version: 1

club:
  name: my-club
  type: software-development        # only value supported in this version
  bootstrapped: false               # flips to true once a can_bootstrap agent has run configure(), see providers.md

repository:
  root: "."
  main_branch: main
  master_contract: MASTER_CONTRACT.md   # or docs/governance/..., .clubs/context/..., or a custom path

documentation:
  product: docs/product/PRODUCT_OVERVIEW.md
  architecture: docs/architecture/SYSTEM_ARCHITECTURE.md
  delivery: docs/delivery/AGENT_OPERATING_MODEL.md
  features: docs/features
  decisions: docs/decisions
  handoffs: docs/handoffs

runtime:
  communication: filesystem
  polling_interval_seconds: 3        # club agent start's sleep between ticks
  heartbeat_interval_seconds: 10     # reserved for future heartbeat-staleness detection
  heartbeat_timeout_seconds: 60      # reserved for future heartbeat-staleness detection
  max_tasks_per_agent: 1             # reserved; not yet enforced beyond eligible_assignee's busy-check
  provider_timeout_seconds: 600      # timeout (subprocess or HTTP) for every real provider call

workflow:
  pattern: planner-developer-reviewer-coordinator   # one of the 5 patterns, see patterns.md

agents:
  planner:
    role: planner
    shell: dedicated                 # reserved; not yet used to spawn a real terminal
    can_plan: true
    can_code: false
    can_review: false
    can_assign: false
    can_merge: false
    can_bootstrap: false              # see providers.md#autonomous-bootstrap-can_bootstrap
    provider: dummy                   # dummy | shell | claude | codex | ollama | openai | gemini | openrouter
    provider_command: null            # required (a shell command) only when provider: shell
    provider_model: null              # optional model override for ollama/openai/gemini/openrouter
    provider_base_url: null           # optional endpoint override, mainly for ollama
  developer:
    role: developer
    can_code: true
    provider: claude
    provider_command: null
  # ...one entry per agent, generated by patterns.py for whichever pattern you chose
```

## Notes

- **`agents`** keys are the agent ids used everywhere else (`club agent start <id>`,
  `.clubs/runtime/state/<id>.json`, task `owner.agent_id`). Role names must match
  `^[a-z][a-z0-9-]*$`.
- **Capabilities** (`can_plan`/`can_code`/`can_review`/`can_assign`/`can_merge`)
  determine which `Provider` methods `runtime.run_agent_tick` calls for that agent —
  see [architecture.md](architecture.md#the-poll-tick). They're independent of
  `provider`: an agent's *capabilities* say *what* it's allowed to do; its `provider`
  says *how* (mechanically, via a script, or via a real LLM) it does it.
- **`provider: shell`** requires `provider_command` — `club validate` fails otherwise.
- Editing `club.yaml` by hand is fine; re-run `club validate` after.
